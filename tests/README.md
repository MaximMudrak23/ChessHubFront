# Перевірка реєстрації та входу

`npm test` перевіряє API-контракти й polling без додаткових залежностей.

Ручна перевірка інтерфейсу з backend:

1. За ввімкненої пошти зареєструвати нову адресу. Після `200 { message: "Verification email sent" }` має з’явитися екран очікування.
2. Поки status повертає `{ verified: false }`, екран очікування залишається відкритим, токен не зберігається.
3. Підтвердити пошту. Після `{ verified: true }` має відкритися вкладка Sign In із заповненою поштою та порожнім паролем. Нових status-запитів і автоматичного входу бути не повинно.
4. Ввести пароль і натиснути WELCOME BACK. Перевірити POST `/auth/login` з `{ email, password }`; після успішної відповіді токен має зберегтися, користувач — перейти на `/main`.
5. За вимкненої пошти перевірити реєстрацію з відповіддю `201 { message: "User created", token, user }`: користувач одразу авторизується та переходить на `/main`.
6. Під час очікування вибрати іншу пошту або вкладку Sign In. Polling має зупинитися; запізніла відповідь попереднього запиту не повинна перемикати форму.

# Перемотування ходів

`npm test` включає `move-navigation.test.mjs`: індексацію півходів, FEN, неповну історію, збереження курсора, блокування ходів, відповідь `/game/move`, 409 та гонки HTTP/socket.

Браузерний сценарій без нових залежностей використовує Chromium DevTools, справжні React-компоненти та підмінені HTTP/Socket.IO. Запустіть Vite на `127.0.0.1:5199` та окремий Chromium-сумісний браузер із `--remote-debugging-port=9240` і тимчасовим `--user-data-dir`, потім:

```sh
node tests/browser/move-navigation.mjs
```

Адреси можна змінити через `NAV_ORIGIN` та `NAV_DEBUGGER`. Скрипт перевіряє стрілки, кнопки, кліки на обидві колонки, виділення, поля введення, локальні варіанти в історичних позиціях, скасування drag/promotion, нові ходи й завершення під час перегляду минулого, reconnect, іншу гру, неповну/порожню історію, глядача та мобільну ширину 390 px. Знімок екрана записується в `/private/tmp/chesshub-move-navigation-mobile.png`.

Інтеграція з реальною MongoDB та шаховим рушієм потребує окремого ручного прогону з backend.

Сценарій також перевіряє рух того самого DOM-елемента через CSS transition, підсвічування історичного ходу, запити звуків через підмінений Audio та одноразовий показ результату лише при завершенні живої гри учасника. Вхід у завершену партію, повторний вхід із кешованою активною грою, reconnect, перемотування та режим глядача не відкривають модалку. Налаштування `prefers-reduced-motion` вимикає рух фігур.

Лише у завершеній партії (включно з її минулими позиціями) доступний локальний аналіз за сторону, чия черга. Вигадані ходи не надсилаються на сервер і не додаються до списку ходів. Виділення залишається на ході початку варіанта; стрілки та кнопки проходять записаний початок партії й локальне продовження. Клік на виділений хід або `Return to recorded position` скидає варіант. Новий хід після перемотування замінює локальне продовження. На актуальній позиції активної гри діють звичайні правила участі й серверного відправлення.

Автоматичні тести охоплюють ізоляцію варіанта, перемотування, зміну продовження, оновлення гри, заборону серверних ходів з аналізу, рокіровку та її права, взяття на проході, безпеку короля й усі перетворення. У браузері перевіряються обидва кольори через клік і drag, підсвічування поточної сторони, незмінність сайдбару та серверної гри, скидання варіанта й незавершеного promotion, reconnect та заборона аналізу під час активної гри.
